# ScrollSplit 기획

트랙패드는 자연스러운 스크롤, 마우스는 일반 스크롤. 둘을 동시에 써도 기기마다 알아서 방향을 맞추는 맥 메뉴 막대 앱.

## 1. 왜 만드나

- macOS의 "자연스러운 스크롤"은 트랙패드·마우스 설정 화면이 따로 있어 보여도 실제로는 스위치 하나다. 하나를 바꾸면 다른 것도 바뀐다.
- 그래서 마우스를 꽂을 때마다 껐다 켰다 해야 하고, 트랙패드와 마우스를 번갈아 쓰면 둘 중 하나는 반대로 움직인다.
- 기존 앱(Scroll Reverser, Mos, LinearMouse 등)도 같은 일을 하지만, 업데이트 확인·통계 같은 네트워크 기능이 들어 있거나 기능이 많아 무엇을 하는지 한눈에 보기 어렵다. 손쉬운 사용 권한을 주는 앱이니 **코드가 짧고, 네트워크를 전혀 쓰지 않고, 소스가 공개된** 앱을 원한다.

## 2. 권한: 피할 수 없는 것과 줄인 것

- **손쉬운 사용(Accessibility)**: 다른 앱으로 가는 스크롤 이벤트를 바꾸려면 macOS가 이 권한을 요구한다. 스크롤 방향을 기기별로 바꾸는 앱은 모두 필요하다. 피할 방법은 없다.
  - 대안이었던 "시스템 설정 값을 자동으로 바꾸기"(마우스 연결/해제 감지)는 권한이 필요 없지만, 트랙패드와 마우스를 **동시에** 쓰는 경우를 해결하지 못해 버렸다.
- 이 앱은 **스크롤 이벤트 한 종류만** 본다(이벤트 마스크 = scrollWheel). 키보드·마우스 클릭·커서 이동은 받지 않는다. 입력 모니터링 권한도 요청하지 않는다.
- **네트워크 없음**: 네트워크 코드가 없고, `scripts/check-no-network.sh`가 빌드된 실행 파일에 네트워크 프레임워크·소켓·HTTP 심볼이 없는지 확인한다. 메뉴의 "ScrollSplit 정보…"는 기본 브라우저로 GitHub 페이지를 여는 것이고, 앱 자신은 통신하지 않는다.
- 저장하는 것: `UserDefaults`에 설정 세 개(트랙패드·마우스 자연스러운 스크롤, 일시 정지)뿐. 로그·통계 없음.

## 3. 동작 방식

1. `CGEvent.tapCreate`로 세션 이벤트 탭을 만든다(스크롤 이벤트만).
2. 이벤트가 오면 어느 기기인지 가린다.
   - 트랙패드: 손가락이 닿는 동안 `scrollPhase`(시작·진행·끝), 손을 뗀 뒤 관성은 `momentumPhase`가 붙는다.
   - 휠 마우스: 둘 다 0.
3. 시스템 "자연스러운 스크롤" 설정과 그 기기에 원하는 값이 다르면 세로·가로 이동량을 뒤집는다(줄 단위·고정소수점·픽셀 세 가지 값 모두).
4. 시스템 설정이 바뀌면(`SwipeScrollDirectionDidChangeNotification`) 다시 읽고, 스크롤 중 5초마다도 다시 읽는다. 시스템 설정을 켜든 끄든 메뉴에서 고른 대로 움직인다.

### 알려진 한계 (v0.1)

- **Magic Mouse**는 트랙패드처럼 phase가 붙어서 트랙패드 쪽 설정을 따른다.
- **Logi Options+ 등에서 부드러운 스크롤을 켠 마우스**는 phase 없이 오면 마우스로 잘 분류되지만, 드라이버가 phase를 붙이면 트랙패드로 분류될 수 있다. 실제 기기로 확인 필요.
- 애드혹 서명이라 **새 버전으로 바꾸면 손쉬운 사용 권한을 다시 줘야 한다**(macOS가 서명이 바뀐 앱을 다른 앱으로 본다). 목록에서 ScrollSplit을 빼고(−) 다시 켜면 된다.

## 4. 자원 사용 목표와 근거

| 상태 | CPU | GPU | 메모리 |
|---|---|---|---|
| 가만히 있을 때 | 0% (타이머·폴링 없음, 스크롤할 때만 깨어남) | 0 (그리는 것 없음, 메뉴 막대 아이콘뿐) | 약 20MB |
| 스크롤 중 | 1% 미만 목표 (이벤트당 필드 6개 읽고 쓰기, 트랙패드는 초당 60~120개) | 0 | 변화 없음 |
| 권한 받기 전 | 2초마다 권한 확인(권한 받으면 멈춤) | 0 | — |

실측은 5장.

## 5. 실측 (2026-10-25, M1 Max·macOS 27)

- 가만히 있을 때: CPU 0.0%(5초 간격 7회), 메모리 약 22MB, GPU 작업 기록 없음(`ioreg` AppUsage 비어 있음).
- 1분 동안 트랙패드·마우스 번갈아 스크롤: 누적 CPU 0.57초 → 평균 약 1%, 5초 샘플 최댓값 5.2%. 목표(1% 미만)를 순간적으로 넘는데, 이벤트마다 WindowServer와 메시지를 주고받는 이벤트 탭 자체 비용이라 줄일 여지가 작다.
- 실행 중 네트워크 소켓 0개(`lsof -i`), 디스크에 쓰는 것은 설정 plist뿐.

## 5-1. 검수 기록

- 1차 Codex(GPT-6 Luna): 입력 먹통·외부 전송 없음. 기기 구분 한계, 설정 키 의존, 애드혹 서명 → 문서화·보완.
- 1차 Gemini 조사: 이벤트 탭 타임아웃·권한 회수 시 입력 정지 보고, Hardened Runtime 미적용 시 주입 위험 → 보완.
- 직접 발견한 버그: `UserDefaults(suiteName: NSGlobalDomain)`이 nil이라 시스템 설정을 항상 '켬'으로 읽음 → CFPreferences로 수정.
- 보완: 권한 회수 알림 시 탭 제거, 설정 재확인은 콜백 밖으로, 일시 정지 = 탭 끔, Shift 실행 = 정지 상태 시작, 잠자기 해제 시 재활성화, Hardened Runtime.
- 2차 Codex: "고칠 것 없음, 배포해도 됨".
